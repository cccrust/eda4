# v0.9 — BIN → JSON 解碼工具

## 目標

實作一個 CLI 工具，將 iCE40 bitstream (BIN) 解碼為人類可讀的 JSON 格式，描述 FPGA 的完整配置狀態（LUT init、FF、IO、繞線）。

## 動機

- 目前管線是**唯寫**的：Verilog → synth → PNR → ASC → BIN，無法從 BIN 逆向回推設定
- 缺少類似 icepack `-b`/`-f` 的視覺化輸出，也缺少 tile-by-tile 的配置報表
- 這個工具可作為除錯、驗證、逆向工程的基礎

## 實作方案

### 方案 A（推薦）：新 crate `v2f-bitdecode`

純 library crate，提供 `bin_to_json()` 函式，並附一個 CLI binary。

**理由**：
- 與 `v2f-bitstream` 職責分離（pack/unpack 是不同方向）
- 可以被 `v2f-cli` 或 `v2f-viz` 引用
- 測試獨立

**目錄結構**：
```
v2f-bitdecode/
  src/
    lib.rs          — 公開 API: bin_to_json(), parse_bin(), decode_cram()
    bin_parse.rs    — BIN 解析器（CRC 驗證、frame 萃取）
    cram_decode.rs  — CRAM → tile-level 設定解碼
    json_out.rs     — 產生 JSON 輸出
    lut_decode.rs   — LUT init table decode
  tests/
    decode_test.rs  — 用 fixtures 驗證 roundtrip
```

### 方案 B：`v2f decode` 子命令

直接加到 `v2f-cli`。優點是方便，缺點是職責混雜。可等 v0.9 完成後再整併。

## 實作階段

### Phase 1 — BIN → CRAM（~1 天）

輸入：BIN 檔
輸出：`Cram` 結構（frames vector）

已有基礎：
- `frame.rs` 的 `Frame::from_bytes()`
- `cram.rs` 的 `Cram::new()` + `get_frame_mut()`

需新增：
- `parse_bin(bytes: &[u8]) -> Result<Cram, Error>` 函式
  - 驗證 preamble（32 bytes 全零）
  - 讀取 bit count，驗證與 device 相符
  - 讀取 frame data
  - 驗證 CRC32
  - 推測 device（從 frame 總數反推 HX1K/HX8K/等）

### Phase 2 — CRAM → Tile Iteration（~2 天）

輸入：`Cram`
輸出：每個 tile 的 raw frame bits + metadata

使用 `CramAddrMap` 遍歷所有 tile：
- Logic tile：讀取 7 個 frame 的 33×40 = 1320 bits，依 bit position 分類
- IO tile：讀取 3 個 frame 的 bits

此時的 JSON 輸出：
```json
{
  "device": "hx1k",
  "num_frames": 1008,
  "tiles": {
    "logic_0_0": {
      "type": "logic",
      "pos": { "col": 0, "row": 0 },
      "frames": [0, 1, 2, 3, 4, 5, 6],
      "bits_set": [15, 127, 1023],
      "lut_init": null,
      "ff": null
    },
    "io_0_1": {
      "type": "io",
      "pos": { "col": 0, "row": 1 },
      "frames": [21, 22, 23],
      "pad_assignments": { "0": null }
    }
  }
}
```

### Phase 3 — LUT / FF / IO Decode（~3 天）

根據 Project IceStorm 的 CRAM bit layout 文件：

**Logic Tile 的 7 個 Frame 含義**（參考 icebox/icebox_chipdb）：
- Frame 0: LUT input routing
- Frame 1-4: LUT init values (each LUT has 16 bits, split across frames)
- Frame 5: FF configuration (DFF/LATCH, clock enable, set/reset)
- Frame 6: Carry chain + output routing

**IO Tile 的 3 個 Frame**：
- Pad direction, pull-up, schmitt trigger 等

**JSON output at this phase**：
```json
{
  "device": "hx1k",
  "tiles": {
    "logic_0_0": {
      "type": "logic",
      "pos": {"col": 0, "row": 0},
      "lut0": {
        "init": "0xABCD",
        "inputs": ["I0", "I1", "I2", "I3"],
        "output": "O"
      },
      "ff0": {
        "type": "dff",
        "clock_enable": true,
        "set_reset": "none"
      }
    },
    "io_0_1": {
      "type": "io",
      "pos": {"col": 0, "row": 1},
      "pad0": {
        "direction": "input",
        "pull_up": false
      }
    }
  },
  "routing": {
    "wires": [
      {"from": {"col": 0, "row": 0}, "to": {"col": 1, "row": 0}, "track": 3},
      ...
    ]
  }
}
```

### Phase 4 — Roundtrip 驗證（~1 天）

用 ASC → BIN（現有 packer）→ JSON（新工具）的路徑驗證：
1. 從 fixture ASC 產生 BIN
2. 用 bin2json 解碼回 JSON
3. 驗證 JSON 內容與原始 ASC 一致

## JSON 輸出格式詳情

### 頂層結構

```json
{
  "format": "v2f-bitdecode-v1",
  "device": "hx1k",
  "created_by": "v2f-bitdecode v0.9",
  "bin_source": "input.bin",
  "crc_valid": true,
  "frame_count": 1008,
  "tiles": { ... },
  "summary": {
    "logic_tiles_used": 42,
    "io_tiles_used": 8,
    "lut_count": 38,
    "ff_count": 26,
    "carry_count": 5
  }
}
```

### Logic Tile

```json
"logic_0_0": {
  "type": "logic",
  "pos": { "col": 0, "row": 0 },
  "lut": {
    "init": "0x8000",
    "equation": "Y = I0 & I1 & I2 & I3",
    "input_select": [true, true, true, true]
  },
  "ff": null,
  "carry": null
}
```

### IO Tile

```json
"io_0_1": {
  "type": "io",
  "pos": { "col": 0, "row": 1 },
  "pads": [
    {
      "pad_num": 0,
      "direction": "input",
      "connected": "clk"
    }
  ]
}
```

## 相依性

- `v2f-bitdecode/Cargo.toml`：
  - `v2f-db`（tile 位置、CRAM 定址、device 參數）
  - `v2f-bitstream`（Frame 類型、Cram 結構、FRAME_BITS 常數）
  - `serde` / `serde_json`（JSON 輸出）
  - `clap`（CLI 參數，若需要獨立 binary）

## 測試策略

1. **Unit tests**：BIN parse（valid/invalid CRC）、frame extraction
2. **Fixture test**：用 `_fixtures/minimal_hx1k.asc` → BIN（現有 packer）→ JSON → 驗證 tile count、LUT init 與 fixture 一致
3. **Empty fixture test**：空 CRAM 的 JSON 應顯示所有 tile 為 unused
4. **Roundtrip test**：從 ASC → BIN → JSON，驗證部分內容匹配

## 風險與限制

1. **LUT init decode**：需要完整的 CRAM bit-to-LUT mapping table。目前 `apply_asc_to_cram` 只能寫入 wiring bits，不處理 LUT init。Phase 3 需要實作 LUT init 的讀取（與 `asc.rs` 中 `.lut` 的寫入相反方向）。
2. **IO 連線名稱**：BIN 本身不儲存 signal name。JSON 的 `"connected"` 欄位需要外部 netlist 資訊（如 synthesis JSON）或留空。
3. **多種 CRAM 格式**：iCE40 有 CRAM 和 BRAM 兩種配置區，BRAM decode 不在 v0.9 範圍內。
4. **版本相容性**：不同 iCE40 封裝可能有不同的 tile 排列。先用 `Ice40Device` 的通用參數，個別封裝的差異後續再補。

## 非目標

- 不實作 BIN → Verilog 還原（那需要完整逆向工程，是更大的專案）
- 不實作 BIN → ASC 轉換（iceunpack 已經能做；未來若需要可在 v0.10 補上）
- 不實作 BRAM / DSP 解碼
