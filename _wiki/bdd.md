# BDD — 二元決策圖

二元決策圖（Binary Decision Diagram, BDD）是布林函數的一種正規化（canonical）表示法，以有向無環圖（DAG）的形式表達對輸入變數的決策過程。BDD 是電子設計自動化（EDA）領域中邏輯合成、形式驗證與測試的核心資料結構之一。

## 什麼是 BDD

一個 BDD 將布林函數表示為一個有向無環圖，其中：

- **終端節點（terminal node）**：標記為 0 或 1，代表函數的輸出值。
- **非終端節點（non-terminal node）**：標記為一個輸入變數 x，有兩條出邊——低邊（low/dashed，x=0）與高邊（high/solid，x=1）。
- 對於給定的變數賦值，從根節點沿著對應的邊向下走，最終到達的終端節點即為函數值。

BDD 的核心優點在於其**正規化**特性：對於固定的變數順序，每個布林函數有唯一的 BDD 表示。這使得許多原本困難的操作（如函數等價檢查）變得平凡。

## 歷史發展

BDD 的發展經歷了三個關鍵里程碑：

- **Lee (1959)**：C. Y. Lee 在貝爾實驗室首次提出「二元決策圖」的概念，作為布林函數的一種圖形化表示。當時這項工作並未受到廣泛關注，因為缺乏高效的演算法來操作這種結構。

- **Akers (1978)**：Sheldon B. Akers 重新發現並正式定義了 BDD，將其應用於數位電路的測試與診斷。Akers 的工作奠定了 BDD 在測試領域的基礎，但仍缺少高效的建構與操作演算法。

- **Bryant (1986)**：Randal E. Bryant 發表了劃時代的論文 "Graph-Based Algorithms for Boolean Function Manipulation"，提出了**有序二元決策圖（ROBDD）**。Bryant 證明了在固定變數順序下，可以透過兩個簡單的化簡規則獲得正規化表示，並給出了所有布林操作的多項式時間演算法。這篇論文徹底改變了 EDA 領域，至今已被引用超過萬次。

Bryant 的 ROBDD 被廣泛認為是現代 BDD 的標準形式。1986 年之後，BDD 迅速成為邏輯合成、形式驗證、測試產生等領域的標準工具。

## 決策樹 vs DAG

要理解 BDD 的壓縮能力，可以先考慮樸素的**決策樹（decision tree）**：

- 對於一個 n 輸入的布林函數，完整的決策樹有 2^n 個葉子節點，對應所有可能的輸入組合。
- 樹的節點總數為 2^(n+1) - 1，隨 n 呈指數成長。

BDD 透過兩個關鍵技術將決策樹壓縮為**有向無環圖（DAG）**：

1. **子圖合併（merging）**：當兩個子決策樹完全相同時，只需保留一份，讓多個父節點共用。
2. **冗餘節點消除（elimination）**：如果一個節點的低邊和高邊指向同一個子節點，則該節點是多餘的——因為無論 x 取何值，結果都相同。

透過這兩條規則，許多實用函數的 BDD 大小遠小於決策樹。例如，n 輸入 AND 函數的決策樹有 2^n 個葉子，但其 BDD 只需要 n+1 個節點。

## ROBDD — 化簡有序二元決策圖

Bryant 提出的 ROBDD 建立在三個核心約束之上：

### Ordered（有序）

所有變數在從根到葉子的任何路徑上以固定的順序出現，且每個變數最多出現一次。變數順序由一個全序（total order）決定，例如 π = (x₁, x₂, ..., xₙ)。這保證了圖結構的規律性。

### Reduced（化簡）

應用以下兩條化簡規則直到無法再化簡：

1. **合併等價子圖（Merge）**：如果兩個節點表示相同的布林函數（即具有相同的變數標記和相同的子節點），則將它們合併為一個節點。
2. **消除冗餘節點（Eliminate）**：如果一個節點的 low 和 high 邊指向相同的子節點，則刪除該節點，並將其所有入邊直接重定向到該子節點。

### 正規性

在固定變數順序下，ROBDD 是**正規化（canonical）**的：兩個布林函數等價若且唯若它們的 ROBDD 完全相同。這一性質的巨大優勢在於：

- 函數等價檢查退化為圖結構比較（指標比較，O(1)）。
- 檢查函數是否為常數 0 或常數 1 退化為檢查 ROBDD 是否為單一終端節點。
- 檢查函數是否為某變數的函數（如是否為 tautology）變得非常簡單。

## ROBDD 的性質

### 優點

- **正規化表示**：等價檢查為常數時間。
- **緊湊性**：對許多實用函數，BDD 大小遠小於 2^n。例如：
  - 對稱函數（symmetrical function）的 BDD 大小為 O(n²)。
  - ALU 電路（如加法器）的 BDD 大小為 O(n)。
  - 多數多輸出電路的 BDD 大小落在合理範圍內。
- **操作效率**：所有二元布林操作（AND、OR、XOR 等）的時間複雜度為 O(|G₁|·|G₂|)，其中 |G| 為 BDD 節點數。

### 限制

- **變數順序敏感性**：BDD 大小高度依賴變數順序。最佳順序與最差順序可能差別指數級。例如，對於 n 位元乘法器的某個輸出位元，最佳順序可能需要 O(2^n) 節點。
- **乘法器**：無論採用何種變數順序，乘法器的 BDD 大小均為指數級（這是已知的理論下限）。
- **隱藏加權位元函數（Hidden Weighted Bit）**：同樣存在指數級下界。
- **記憶體消耗**：對於大型設計（數百個輸入），BDD 可能耗盡記憶體。工業界的 BDD 應用通常限制在 50–200 個輸入的範圍內。

## 變數順序

變數順序是 BDD 應用中最關鍵的實務問題。良好的順序可以讓 BDD 保持小巧，惡劣的順序則導致狀態爆炸。

### 最佳順序 vs 最差順序

考慮布林函數 f = x₁x₂ + x₃x₄ + ... + x_(2n-1)x_(2n)：

- 最佳順序：π = (x₁, x₂, x₃, x₄, ..., x_(2n))，BDD 大小為 2n+1。
- 最差順序：π = (x₁, x₃, x₅, ..., x₂, x₄, x₆, ...)，BDD 大小為 O(2^n)。

差異原因：好的順序將相關變數放在一起，讓低層的子圖可以被高層共用。

### 啟發式方法

- **fan-in/fan-out 啟發**：根據電路的連線結構決定變數順序。通常，拓撲排序（從輸入到輸出）能給出不錯的結果。
- **動態重排序（Dynamic Reordering）**：在建構 BDD 的過程中，當節點數超過閾值時觸發重新排序。
  - **Sifting**：逐一將每個變數移動到所有可能位置，選擇最佳位置。時間複雜度 O(n²)。
  - **Window 重排序**：在滑動窗口內對變數進行排列，找到局部最佳順序。
  - **群組翻轉（Group Inversion）**：將變數分組，在組內進行排列。

動態重排序可以在 95% 以上的案例中找到接近最佳的順序。

## BDD 上的布林操作

BDD 上的所有布林操作都以遞迴的方式實現，核心是 **ITE（If-Then-Else）** 操作。

### ITE 運算子

ITE 是一個三參數的通用運算子：

```
ITE(F, G, H) = F · G + F' · H
```

其中 F、G、H 均為布林函數。ITE 可以表達所有二元布林操作：

| 操作 | ITE 表示 |
|------|----------|
| NOT(F) | ITE(F, 0, 1) |
| AND(F, G) | ITE(F, G, 0) |
| OR(F, G) | ITE(F, 1, G) |
| XOR(F, G) | ITE(F, NOT(G), G) |
| NAND(F, G) | ITE(F, NOT(G), 1) |
| NOR(F, G) | ITE(F, 0, NOT(G)) |
| IMP(F, G) | ITE(F, G, 1) |

### ITE 演算法

ITE 的計算採用遞迴方式，利用 Shannon 展開：

如果 F = ITE(x, F₁, F₀)，則：

```
ITE(F, G, H) = ITE(x, ITE(F₁, G₁, H₁), ITE(F₀, G₀, H₀))
```

其中 G₁ = cofactor of G w.r.t. x=1，依此類推。

實作中使用**計算表（computed table）**來避免重複計算，這是一個以 (F, G, H) 為鍵的雜湊表。加上 **唯一表（unique table）**來確保節點的唯一性（合併等價節點）。

ITE 操作的時間複雜度為 O(|F|·|G|·|H|)，但在實務中通常遠小於上界。

### Complement Edge（補邊）

為了進一步壓縮 BDD 大小，現有的 BDD 套件（如 CUDD）通常實作**補邊（complement edge）**。補邊在邊上標記是否對子函數取補。這樣做的好處是：

- NOT 操作變為常數時間（只需翻轉邊標記）。
- 終端節點只需一個 1 節點。
- 節點總數減少約 30–40%。

## BDD 在 EDA 中的應用

### 邏輯合成

BDD 在邏輯合成中有多種用途：

- **布林函數操作**：對大規模布林函數進行 AND、OR、XOR 等操作。
- **tautology 檢查**：檢查一個函數是否恆為 1（對 ROBDD 而言只需檢查是否為常數 1 節點）。
- **蘊含檢查（implication check）**：檢查是否 F → G，即 ITE(F, NOT(G), 0) 是否為常數 0。
- **無關項計算**：SAT 與 ODC（Observability Don't Care）的計算。
- **邏輯最佳化**：透過 BDD 操作進行布林化簡與重組。

### 形式驗證

BDD 在形式驗證中有悠久的應用歷史：

- **等效檢查（Equivalence Checking）**：比較兩個電路的輸出函數是否等價。由於 ROBDD 的正規化特性，只需檢查兩者的 ROBDD 是否相同。這是 BDD 最經典的應用。
- **模型檢查（Model Checking）**：使用 BDD 表示狀態轉移關係和一組狀態，透過定點計算驗證時序屬性。McMillan 在 1990 年代提出的符號模型檢查（Symbolic Model Checking, SMC）就是奠基於 BDD。
- **SMV 模型檢查器**：第一款基於 BDD 的符號模型檢查工具，由 McMillan 在卡內基梅隆大學開發。

### 測試

- **測試樣本生成**：使用 BDD 計算布林差（Boolean difference）來產生測試樣本。
- **錯誤分析**：透過 BDD 表示錯誤函數（fault function）來分析錯誤的傳播。
- **自動測試樣本產生（ATPG）**：基於 BDD 的 ATPG 演算法可以處理中等規模的電路。

### 技術映射

BDD 在技術映射（technology mapping）中也有應用：

- **DAG 覆蓋（DAG Covering）**：將布林網路分解為可對應到標準細胞庫的子圖。BDD 可以用來高效地計算子圖的多種實現方式。
- **模式匹配**：透過計算函數的 BDD 來快速比對標準細胞庫中的模式。

## BDD 與其他表示法的比較

| 表示法 | 正規化 | 空間效率 | 操作效率 | 適用場景 |
|--------|--------|----------|----------|----------|
| Truth Table（真值表） | 是 | 極差（2^n） | O(2^n) | 小型函數驗證 |
| SOP（積和式） | 否 | 中等 | 高（Espresso） | 邏輯化簡、PLA |
| Circuit（電路） | 否 | 最好 | 中等 | 大規模設計 |
| BDD | 是 | 好 | 好 | 形式驗證、合成 |
| AIG | 否（結構性） | 最好 | 極好 | 大規模合成 |
| SAT | 否 | 最好 | 中等 | 驗證、求解 |

BDD 的獨特優勢在於正規化——這是其他表示法（除了真值表）不具備的。而真值表雖然也是正規化的，但其空間效率遠不及 BDD。

## 字級決策圖（Word-Level Decision Diagrams）

對於算術電路，位元級 BDD 通常效率不佳（如乘法器需要指數級節點）。為了解決這個問題，研究人員提出了字級決策圖：

- **BMD（Binary Moment Diagram）**：使用 *x* 和 1−x 的線性組合來表示函數，對乘法器有線性大小的表示。BMD 的邊權重為整數，終端節點也為整數。
- ***MTBDD（Multi-Terminal BDD）***：終端節點可以取多種值（不限於 0/1），適合表示偽布林函數（pseudo-Boolean function）。
- **HDD（Hybrid Decision Diagram）**：混合了位元級和字級的決策變數。
- **EVBDD（Edge-Value BDD）**：邊上帶整數權重的 BDD。

這些字級決策圖在**高階合成**和**算術電路驗證**中有重要應用。

## 限制與挑戰

儘管 BDD 非常強大，但它有幾個根本性的限制：

1. **指數級下界**：存在一類函數（乘法器、HWB）無論採用何種變數順序，其 BDD 大小都為指數級。這意味著 BDD 不適合處理所有布林函數。對於這類函數，BDD 的記憶體消耗會迅速超出可用資源。
2. **順序敏感性**：BDD 的大小高度依賴於變數順序。雖然動態重排序在大多數情況下有效，但它本身可能非常耗時，且在極端情況下可能無法找到可接受的順序。對於某些不規則的電路結構，變數順序的搜尋空間過大，導致重排序本身成為瓶頸。
3. **記憶體消耗**：對於大型設計，BDD 可能消耗數 GB 的記憶體。這限制了 BDD 在工業級超大規模設計中的應用。工業界通常將 BDD 的應用範圍限制在 50–200 個輸入的電路。
4. **正規化的代價**：為了維持正規化，BDD 在某些操作上比非正規化表示（如 AIG）更昂貴。特別是在 BDD 成長為大型結構時，ITE 遞迴操作的時間開銷顯著增加。
5. **動態操作開銷**：當對 BDD 進行大量操作時，唯一表和計算表的維護成本不可忽視。記憶體管理（節點回收、垃圾收集）也為 BDD 套件增加了複雜性。
6. **應用場景限制**：在 SAT 求解、ATP 等場景中，CNF（Conjunctive Normal Form）表示往往比 BDD 更高效。BDD 的優勢主要體現在需要正規化表示的場景。

這些限制推動了 AIG（And-Inverter Graph）和 SAT 求解器等替代技術的發展。在當前的 EDA 流程中，BDD 和 AIG/SAT 各有其適用場景：

| 場景 | 推薦技術 | 原因 |
|------|----------|------|
| 函數等效檢查 | BDD 或 SAT | BDD 正規化檢查為 O(1)，SAT 適合大規模 |
| 邏輯合成最佳化 | AIG | 可擴展到百萬閘，支援豐富的重寫技術 |
| 模型檢查 | BDD 或 IC3/PDR | BDD SMV 經典方案，IC3 適合更大規模 |
| 測試樣本生成 | SAT 或 BDD | SAT 更適合大電路，BDD 更適合綜合分析 |
| FPGA LUT 映射 | AIG | AIG 的 cuts 計算效率極高 |
| 小規模布林分析 | BDD | 正規化帶來極大的便利性 |

## BDD 與真值表、SOP、電路的比較

在 EDA 工具中，布林函數有多種表示方式，各有優劣：

### 真值表（Truth Table）

真值表是最直觀的表示方式——列出所有輸入組合對應的輸出值。

- **優點**：完全正規化，直觀易懂。
- **缺點**：大小固定為 2^n，隨輸入數指數增長。僅適合 20 輸入以內的函數。
- **應用**：LUT init 的計算、小型驗證問題。

### 積和式（SOP, Sum-of-Products）

SOP 是邏輯化簡的傳統表示法（即 PLA 格式），由多個乘積項（cube）構成。

- **優點**：Espresso 演算法可以高效地對 SOP 進行化簡；與 PLA/ROM 直接對應。
- **缺點**：不正規化——同一個函數有多種 SOP 表示；大小在最差情況下仍為指數級。
- **應用**：邏輯化簡、PLA 生成、技術映射中的模式匹配。

### 電路（Circuit / Netlist）

網表是按閘極連接方式表示的結構性描述。

- **優點**：最緊湊的表示法，可擴展到數千萬閘；最接近物理實現。
- **缺點**：最不正規化——同一函數有無限多種電路實現；等價檢查需要進行複雜的驗證。
- **應用**：所有大規模硬體設計。

### BDD

BDD 處於真值表和電路之間，兼具正規化和一定程度的緊湊性。

- **優點**：正規化，支援多項式時間的操作，對對稱函數和有規律結構的函數很緊湊。
- **缺點**：對某些函數（乘法器）必定指數級，對變數順序敏感，記憶體開銷較大。
- **應用**：形式驗證、邏輯合成、測試生成。

### AIG

AIG 是 ABC 的核心表示法，在可擴展性和操作效率之間取得了最佳平衡。

- **優點**：結構性雜湊提供近似正規化，支援百萬閘級別，重寫操作極快。
- **缺點**：不正規化（結構性雜湊不等於函數正規化），缺乏布林推理的完備支援。
- **應用**：大規模邏輯合成、FPGA 映射、等效檢查。

## BDD 套件實作考量

實作一個高效的 BDD 套件需要考慮多個工程問題：

### 唯一表（Unique Table）

唯地以雜湊表維護所有節點，確保每個節點是唯一的。鍵值為 (var, low, high) 三元組。這是 ROBDD 正規化的基礎。

### 計算表（Computed Table）

快取 ITE 操作的結果，避免遞迴過程中的重複計算。計算表是 BDD 操作效率的關鍵——沒有計算表的 BDD 套件會呈指數級退化。

### 記憶體管理

BDD 節點數量可達數百萬，高效的記憶體管理是必須的：

- **節點池（node pool）**：預先分配大塊記憶體來存放節點，減少 malloc 開銷。
- **參考計數（reference counting）**：追蹤每個節點的被引用次數，自動回收不再使用的節點。
- **垃圾收集（garbage collection）**：定期回收孤兒節點，壓縮記憶體使用。

### Complement Edge 的實作

大多數現代 BDD 套件使用補邊來提升效率。實作細節包括：

- 用最低位元（LSB）作為補邊標記。
- 終端節點只保留常數 1（常數 0 由常數 1 加上補邊表示）。
- 補邊在 ITE 操作中需要特殊處理，確保正規化不被破壞。

### 變數順序管理

BDD 套件需要支援變數順序的查詢、設定和動態重排序：

- 變數順序以陣列或連結串列維護。
- Sifting 演算法需要能夠將一個變數移動到任意位置，並增量更新受影響的節點。
- 重排序時需要重建唯一表中受影響的條目。

知名的 BDD 套件包括 CUDD（科羅拉多大學）、BuDDy（邦大學）、JDD（Java）和 CAL。

## BDD 在 eda4 中的角色

在 eda4 專案中，`verilog2fpga` 的合成管線（`v2f-synth`）目前**沒有使用 BDD**：

- 合成流程是直接的：Verilog 解析 → 技術映射（techmap） → 網表生成 → JSON 輸出。
- LUT 初始值（LUT init）的計算透過直接的真值表建構來完成，而非使用 BDD 操作。
- 合成採用了**基於規則的技術映射**，逐個 Verilog 元件映射到 iCE40 邏輯單元。

### 為何不使用 BDD

V2f-synth 不採用 BDD 的主要原因：

1. **設計規模**：目前的目標設計（blinky、adder 等）規模很小，真值表建構已足夠。
2. **實作複雜度**：引入 BDD 需要完整的 BDD 套件，包含唯一表、計算表、記憶體管理等，工程成本較高。
3. **最佳化目標**：純 Rust 合成目前的目標是功能正確而非最佳化，BDD 帶來的最佳化收益在當前的應用場景中不顯著。
4. **替代方案成熟**：當需要高品質合成時，直接呼叫 yosys+ABC 是更現實的選擇。

### 未來引入 BDD 的可能性

未來，BDD 可以引入 `v2f-synth` 的以下環節：

- **LUT init 最佳化**：使用 BDD 來重組和化簡 LUT 的布林函數，減少 LUT 數量或深度。特別是當 Verilog 設計包含複雜的組合邏輯時，BDD 可以幫助將函數分解為更適合 LUT 實現的形式。
- **冗餘邏輯消除**：使用 BDD 檢測和消除電路中的冗餘節點——例如兩個邏輯等效的信號驅動同一個 LUT 的情況。
- **等效檢查**：在測試中，使用 BDD 驗證純 Rust 合成結果與 yosys 輸出是否等效。這是一個高效的迴歸測試方案。
- **無關項傳播**：使用 BDD 計算觀測無關項（ODC），進一步最佳化邏輯，減少不必要的邏輯翻轉。
- **技術映射中的模式匹配**：使用 BDD 作為函數簽名來快速查找標準細胞庫中的匹配模式。

如果在 Rust 生態系中找到一個輕量級的 BDD 函式庫，或者在 v2f-synth 中需要處理更複雜的布林邏輯時，引入 BDD 將成為一個合理的架構決策。
