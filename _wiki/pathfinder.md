# PathFinder：FPGA 協商式擁塞繞線演算法

## 什麼是 PathFinder

PathFinder 是 FPGA 繞線領域最具影響力的演算法之一，由 Larry McMurchie 與 Carl Ebeling 於 1995 年提出。其核心貢獻是引入了**協商式擁塞**（Negotiated Congestion）的概念：不同於傳統繞線方法試圖一次性地為所有網路找到無衝突路徑，PathFinder 採用疊代式的「解除繞線—重新繞線」（rip-up and reroute）策略，逐步讓競爭同一繞線資源的網路協商出各自的路徑。

PathFinder 的關鍵洞察在於：與其試圖避免衝突，不如先繞線再解決衝突。在每一輪疊代中，每個網路都被重新繞線，同時考慮歷史擁塞資訊來引導決策。這種方法保證最終收斂到一個無衝突的繞線方案，且在高擁塞的 FPGA 繞線環境中表現出色。

PathFinder 是眾多學術與商業 FPGA 繞線工具的基石，包括 VPR（Versatile Packing and Routing）和開源的 nextpnr。理解 PathFinder 對於設計和評估任何 FPGA 繞線器都具有根本性的意義。

## 歷史背景

PathFinder 演算法由 Larry McMurchie 和 Carl Ebeling 在華盛頓大學（University of Washington）開發，於 1995 年在 ACM/SIGDA 國際 FPGA 研討會上發表，論文題為 "PathFinder: A Negotiation-Based Performance-Driven Router for FPGAs"。

在 PathFinder 出現之前，FPGA 繞線主要依賴兩類方法：

1. **一次性全域繞線**：先將所有網路的路徑全局分配，再逐個詳細繞線。這種方法在處理擁塞時缺乏彈性，早期決策的錯誤會傳播到後續階段。

2. **基於通道的繞線**：將其應用於 FPGA 時面臨架構上的限制，因為 FPGA 的繞線架構是預先製造的，不像 ASIC 的繞線通道可以靈活調整寬度。

McMurchie 與 Ebeling 的靈感來自於觀察到 FPGA 繞線問題與通訊網路中的流量控制有著深層的類比：多個網路如同多個資料流，競爭有限的繞線資源（通道、開關）。借鑒 TCP 的擁塞控制思想，他們設計了一種讓網路在競爭中「協商」出資源分配的機制。

PathFinder 的發表對 FPGA EDA 領域產生了深遠影響。此後的學術繞線器（如 VPR 4.0、VPR 5.0、VPR 8.0）以及商用 FPGA 工具鏈都採用了或借鑑了 PathFinder 的核心思想。

## FPGA 繞線問題

在理解 PathFinder 之前，需要先清楚 FPGA 繞線問題的特殊性。

### 預製繞線架構

與 ASIC 不同，FPGA 的繞線資源在晶片製造時就已完全固定。FPGA 晶片包含大量預先鋪設的繞線通道（wire segments）和可程式化開關（programmable switches），繞線器的任務是在這個固定的拓撲結構中選擇合適的路徑。

以 iCE40 架構為例，每個邏輯磚塊（logic tile）之間存在：
- **水平繞線通道**：連接相鄰磚塊
- **垂直繞線通道**：連接上下磚塊
- **開關方塊（switch box）**：允許訊號在不同方向的繞線通道之間切換
- **連接方塊（connection box）**：允許訊號進入或離開邏輯磚塊

### 繞線問題的形式化

給定一個已放置的電路網表，FPGA 繞線問題可以形式化為：

- **輸入**：
  - 一組網路（nets）\( N = \{n_1, n_2, ..., n_k\} \)，每個網路連接一組已放置的終端
  - 一組繞線資源（routing resources）\( R = \{r_1, r_2, ..., r_m\} \)，每個資源有容量 \( c(r) \)（通常為 1）
  - 資源之間的連接拓撲

- **輸出**：
  - 為每個網路 \( n_i \) 找到一組連通的繞線資源 \( S_i \subseteq R \)，使得：
    - \( S_i \) 連接該網路所有終端
    - 對任意資源 \( r \)，使用該資源的網路數量 \( usage(r) \leq c(r) \)

- **最佳化目標**：
  - 最小化繞線總長度
  - （可選）滿足時序約束

當一個資源被超過 capacity 個網路使用時，稱為**溢位**（overflow）。

### 困難之處

FPGA 繞線的困難來自以下幾個方面：

1. **全域性**：網路的繞線決策相互依賴。一個網路選擇了某條路徑，就剝奪了其他網路使用相同資源的機會。

2. **NP-hard 本質**：同時繞線所有網路的最優化問題是 NP-hard 的。即使只考慮兩個終端的繞線（Steiner 樹問題），在多資源約束下也極為複雜。

3. **預製限制**：不像 ASIC 繞線可以增加新的繞線層或調整通道寬度，FPGA 的繞線拓撲是固定的，繞線器只能在既有資源中取捨。

## PathFinder 的核心洞察

PathFinder 的關鍵洞察在於重新定義了問題的解決策略：

**傳統思維**：「先將資源分配好，再繞線」或「繞線時避免衝突」

**PathFinder 思維**：「先繞線，再解決衝突」

這種「先繞後修」的策略初看似乎反直覺——既然知道資源有限且可能衝突，為什麼不事先避免？

原因是：對於大型 FPGA 設計，不可能一開始就知道哪些資源會被競爭。一個網路的最短路徑可能正好經過某個關鍵瓶頸區域，但這個瓶頸區域只有在所有網路都嘗試繞線後才會顯現。

PathFinder 的「協商」機制正是為了解決此問題：
- 初始：所有網路都選擇對自己最有利的路徑（通常是 A* 最短路徑）
- 衝突發生後：提升衝突資源的「成本」，讓網路被迫重新考慮替代路徑
- 疊代：重複此過程，讓網路逐步讓出過度競爭的資源
- 收斂：最終每個網路找到一條可行的路徑，且所有資源使用量不超過容量

這個過程類似於人類的協商：當多個人同時爭奪同一資源時，先各自提出需求，發現衝突後，再相互讓步，最終達成一個各方都可接受的分配方案。

## 成本函數

PathFinder 的核心是其精心設計的成本函數。每個繞線節點（node，即一個繞線資源）的成本由兩部分組成：

### 公式

```
cost(node) = b(node) × h(node) × p(node)
```

其中：
- **\( b(node) \)**：基本成本（base cost），使用該資源的固有代價，通常與資源的物理特性相關（如線段長度、開關類型）
- **\( h(node) \)**：歷史擁塞因子（historical congestion factor），累積了過去疊代中該節點的擁塞程度
- **\( p(node) \)**：當前擁塞因子（present congestion factor），反映當前疊代中該節點被多少網路使用

### 各項因子的詳細說明

#### 基本成本 \( b(node) \)

基本成本反映了使用一個繞線資源的固有代價。在一般實作中：
- 短線段的成本低於長線段（鼓勵使用短線以節省資源）
- 開關點的成本可能略高於直通線段（因為開關有延遲）
- 通常設為 1 作為基準

#### 歷史擁塞因子 \( h(node) \)

歷史擁塞因子是 PathFinder 最關鍵的創新之一。它的作用類似於「長期記憶」：

```
h_i(node) = h_{i-1}(node) + 1    若 node 在上一次疊代中有溢位
h_i(node) = h_{i-1}(node)         若 node 無溢位
```

也就是說，每次疊代中如果某個節點被過度使用，它的歷史擁塞因子就增加 1。這個值從不減少（在某些變體中可衰減），確保了：

- **記憶效應**：即使當前的繞線方案暫時解決了某個資源的衝突，歷史記錄仍然存在，防止演算法退回原來的衝突狀態
- **避免震盪**：這是 PathFinder 保證收斂的關鍵——如果沒有歷史因子，演算法可能會在兩個方案之間來回震盪

#### 當前擁塞因子 \( p(node) \)

當前擁塞因子反映某一節點在當前疊代中的使用情況：

```
p(node) = 1 + max(0, usage(node) - capacity(node))
```

- 若 \( usage(node) \leq capacity(node) \)，則 \( p(node) = 1 \)（無額外懲罰）
- 若 \( usage(node) > capacity(node) \)，則 \( p(node) = 1 + overflow \)（溢位懲罰）

當前擁塞因子讓網路在當下疊代中避開已過度使用的節點，而歷史因子確保了網路不會重複犯同樣的錯誤。

### 網路的總成本

一個網路使用一組節點 \( S \) 的總成本為：

```
cost(net) = Σ_{node in S} b(node) × h(node) × p(node)
```

在 A* 搜尋中，從起點到當前節點的實際成本 \( g \) 累加路徑上所有節點的 `b × h × p`，而啟發式函數 \( h \)（通常為曼哈頓距離或預估最短路徑成本）則用於引導搜尋方向。

## 演算法流程

PathFinder 的完整流程如下：

### 初始化階段

1. 設定所有節點的歷史擁塞因子 \( h(node) = 1 \)
2. 設定所有節點的當前使用計數 \( usage(node) = 0 \)

### 主疊代循環

```
procedure PathFinder(N, R):
    for each node r in R:
        h(r) = 1

    repeat:
        // 階段 1：解除所有網路的繞線
        for each net n in N:
            rip_up(n)

        // 階段 2：重新繞線所有網路
        for each net n in N:
            S_n = A_Star_Route(n, R, cost)

        // 階段 3：更新資源使用統計
        overflow_found = false
        for each node r in R:
            usage(r) = count_nets_using(r)
            if usage(r) > capacity(r):
                overflow_found = true
                h(r) = h(r) + 1

        // 階段 4：檢查收斂條件
        if not overflow_found:
            return SUCCESS

        // 階段 5：更新當前擁塞因子
        for each node r in R:
            p(r) = 1 + max(0, usage(r) - capacity(r))

        // 可選：限制最大疊代次數
        if iterations > MAX_ITERS:
            return FAILURE

    end repeat
```

### 解除繞線與重新繞線

在每個疊代中，需要先解除所有既有繞線路徑，然後用當前的擁塞資訊重新繞線。

解除繞線的步驟：
1. 從資源使用表中移除該網路所佔用的節點
2. 清空該網路的繞線路徑

重新繞線的步驟：
1. 在資源使用表中標記該網路的終端
2. 使用 Dijkstra/A* 演算法，以當前的成本函數尋找最低成本路徑
3. 將新路徑上的節點標記為被該網路使用

### 收斂保證

PathFinder 的收斂依賴於以下數學性質：

由於歷史擁塞因子 \( h \) 在每次疊代中單調增加（從不減小），且成本函數隨之增長，每個網路的繞線成本在疊代過程中呈現上升趨勢。

對於任意節點 \( r \)，如果它被過度使用 \( k \) 次，則 \( h(r) \) 至少增加 \( k \)。當 \( h(r) \) 足夠大時，任何網路的 A* 搜尋都會傾向於避開該節點，轉而尋找替代路徑。

關鍵在於：替代路徑的存在性由 FPGA 繞線架構的冗餘度保證。如果架構本身就是不可繞線的（通道不足），PathFinder 會檢測到無法收斂的情況，此時需要修改設計或調整架構。

### A* 繞線子程序

PathFinder 使用 A*（或 Dijkstra）演算法來為單個網路尋找最低成本路徑。A* 的評價函數為：

```
f(node) = g(node) + h(node)
```

- \( g(node) \)：從起點到當前節點的實際路徑成本，等於路徑上所有節點 \( b × h × p \) 的累加
- \( h(node) \)：從當前節點到終點的估計成本（可接納的啟發式函數）

對於多終端網路（multi-terminal net），PathFinder 使用**逐步 Steiner 樹**建構法：

1. 初始化 Steiner 樹，包含網路的源頭終端
2. 重複以下步驟，直到所有終端都被包含：
   - 使用 A* 尋找樹中任一節點到最近未連接終端的最短路徑
   - 將該路徑及終端加入 Steiner 樹
3. 最後對整棵 Steiner 樹進行選擇性移除冗餘分支（branch pruning）

### 時序驅動版本

PathFinder 的原始論文同時提出了時序驅動的變體，稱為**時序驅動 PathFinder**（Timing-Driven PathFinder）。

其核心修改是在成本函數中引入**時臨界度**（criticality）因子：

```
cost(node) = b(node) × h(node) × p(node) × crit(net)
```

或更常見的形式：

```
cost(node) = b(node) × [h(node) × p(node)] × (1 - crit(net)) + crit(net) × delay(node)
```

其中 \( crit(net) \) 基於該網路的時序寬裕度（slack）計算：
- 寬裕度越小的網路（時序越緊迫），臨界度越高
- 臨界度範圍通常在 [0, 1] 之間
- 時序關鍵網路的繞線趨向於走最短路徑（最小化延遲），即使通過擁塞區域也在所不惜
- 非關鍵網路的繞線則更傾向於避開擁塞區域

時序驅動版本的實現需要一個靜態時序分析（STA）引擎來計算每個網路的寬裕度，這增加了實作的複雜度，但對於生產級 FPGA 設計至關重要。

## 與 v2f-pnr 繞線策略的比較

eda4 專案的 v2f-pnr crate 實現了一套簡化的繞線器，與 PathFinder 有著方法論上的異同。

### v2f-pnr 的繞線策略

v2f-pnr 的繞線器位於 `v2f-pnr/src/route.rs`，其核心流程如下：

1. **擁塞地圖初始化**：建立一個空的 `HashMap<TileCoord, u32>` 作為擁塞計數器

2. **迭代繞線**（最多 5 次）：
   - 對每個網路，使用 A* 搜尋 Find 一條路徑
   - A* 成本包含繞線長度 + 擁塞懲罰（penalty × 10）
   - 繞線完成後將使用到的磚塊擁塞計數加 1

3. **擁塞衰減**：每次疊代後將所有擁塞計數減 1（防止永久性懲罰）

### 與 PathFinder 的差異

| 特性 | PathFinder | v2f-pnr |
|------|-----------|---------|
| **歷史擁塞** | 累積增加，永不衰減 | 每次疊代衰減，無長期記憶 |
| **溢位檢測** | 明確計算每個資源的溢位 | 無顯式溢位計算 |
| **收斂保證** | 有（歷史因子單調增加） | 無（可能震盪） |
| **每輪重新繞線** | 解除所有網路再全部重繞 | 在先前的路徑基礎上增量繞線 |
| **最大疊代次數** | 不強制限制（至收斂） | 上限 5 次 |
| **擁塞模型** | 資源級別（每個開關/線段） | 磚塊級別（每個 tile） |
| **資源容量** | 明確的 capacity 參數 | 隱含（容量 = 1） |

### PathFinder 可能改進 v2f-pnr 的方向

1. **引入歷史擁塞因子**：將 `congestion` HashMap 的更新策略改為累積式（永不衰減），而非每次衰減，可以避免 5 次疊代後的震盪問題。

2. **顯式溢位檢測**：在每次疊代後計算哪些資源被過度使用，並據此調整成本，而非簡單地增加所有使用過的資源的懲罰。

3. **完全重新繞線**：在每次疊代中，解除所有網路並重新繞線，而非保留先前的路徑。這可以避免「先繞線的網路佔據優勢」的問題。

4. **收斂檢測**：當所有資源的溢位為 0 時提前終止，而非固定 5 次疊代後必然結束。

這些改進可以在保持 v2f-pnr 簡單性的前提下，大幅提升其繞線品質和穩定性。

## PathFinder 為何有效

PathFinder 的有效性可從以下幾個角度理解：

### 從博弈論視角

PathFinder 的疊代繞線過程類似於一個非合作賽局：每個網路都是一個理性的參與者，試圖最小化自己的繞線成本。歷史擁塞因子相當於一種「反壟斷」機制，當一個資源被過度使用時，它的成本會持續上升，直到某些網路決定「讓步」。

這與博弈論中的**勢函數**（Potential Function）存在深度關聯。可以證明 PathFinder 的成本函數對應於一個嚴格的勢函數，這意味著每一次疊代都會降低整個系統的總成本，最終收斂到一個 Nash 均衡。

### 從機器學習視角

PathFinder 可被視為一種強化學習形式：
- **狀態**：目前的繞線方案（每個網路的路徑選擇）
- **行動**：對一個網路選擇新的路徑
- **獎勵**：負的繞線成本（獎勵越小越好）
- **記憶**：歷史擁塞因子累積了過去的「失敗經驗」

每次疊代都類似於學習中的一次「經驗回放」：演算法從過去的錯誤中學習，並在下次決策時避開已知的陷阱。

### 從物理類比視角

PathFinder 可類比為多個彈性繩同時通過一個圓環：
- 每一根繩子都想走最短的路徑（直線通過圓環）
- 但圓環的容量有限，容納不下所有繩子
- 當繩子被強行拉直時（疊代 1），多根繩子卡在同一個圓環中
- 每次疊代如同一次「抖動」，繩子在圓環處被施加額外的阻力（歷史擁塞成本）
- 經過多次抖動後，部分繩子被迫繞道而走其他圓環
- 最終每根繩子找到一條未被阻塞的路徑

### 收斂速度的影響因素

PathFinder 收斂所需的疊代次數取決於：

1. **擁塞程度**：資源越緊缺，需要的疊代次數越多
2. **繞線架構冗餘度**：冗餘路徑越多，替代方案越容易找到
3. **網路規模**：網路數量越多，後續疊代的干擾越大
4. **初始繞線品質**：即 A* 啟發式函數的精準度

在實務中，典型的 PathFinder 收斂需要 20-100 次疊代，對於大型設計可能需要更多。

## PathFinder 在業界的應用

### VPR（Versatile Packing and Routing）

VPR 是加拿大 University of Toronto 開發的學術 FPGA CAD 工具，其繞線引擎基於 PathFinder：
- VPR 的繞線器完全採用 PathFinder 的協商式擁塞機制
- 支援時序驅動繞線（基於 STA）
- 支援多種 FPGA 架構模型
- VPR 8.0 引入了路徑搜尋的加性加權（additive weighting）變體

### nextpnr

nextpnr 是開源 FPGA 工具鏈 Project IceStorm 的官方 PNR 工具，支援 iCE40、ECP5、Nexus 等 FPGA 系列：
- 其繞線引擎基於 PathFinder 思想
- 使用 A* 進行路徑搜尋
- 支援時序驅動繞線
- 實作與 PathFinder 的關鍵差異：
  - nextpnr 使用「疊代加深」策略：從少量疊代開始，必要時增加疊代次數
  - 採用了更複雜的資源圖（包含所有繞線線段和開關）
  - 支援多種啟發式優化（如 bounding box pruning）

### 商用 FPGA 工具

Xilinx 的 Vivado、Intel 的 Quartus 等商用 FPGA 工具也採用了與 PathFinder 類似的疊代式協商繞線策略，雖然具體實作細節各有差異，但其核心思想（歷史擁塞 + 疊代重新繞線）是一致的。

## PathFinder 的變體與擴展

### 時序驅動 PathFinder

如前面所述，透過引入基於時序寬裕度的臨界度因子，PathFinder 可以同時最佳化繞線可行性和時序效能。這是生產級 FPGA 繞線器的標準配置。

### 低功耗 PathFinder

透過在成本函數中加入功耗項，引導繞線器避開高功耗路徑：
- 減少使用長線（長線的電容較大）
- 減少使用開關點（開關會產生動態功耗）
- 合併共用路徑（減少冗餘切換）

### 串擾感知 PathFinder

在深次微米製程中，繞線之間的串擾干擾成為問題。串擾感知的 PathFinder 在成本函數中考慮：
- 平行繞線的長度（平行越長，串擾越大）
- 訊號翻轉率（高速訊號更易造成串擾）

### 多目標 PathFinder

透過加權多目標最佳化，同時考慮繞線長度、時序、功耗、串擾等目標。每個目標各有一個獨立的歷史擁塞因子，最終成本為各項加權和。
