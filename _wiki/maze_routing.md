# Maze Routing (Lee 演算法)

## 什麼是 Maze Routing

Maze Routing（迷宮路由）是在一個網格狀的佈線空間中，尋找兩點之間最短可繞路徑的演算法，同時需要避開所有障礙物。它是電子設計自動化（EDA）領域中最基礎的繞線演算法之一，特別適用於晶片內部的詳細繞線（detailed routing）階段。

核心概念非常直觀：將佈線區域抽象為一個二維網格，每個網格單元代表一個可用的繞線軌道交點，已被佔用的單元視為障礙。演算法從起點開始，像水波一樣向外擴散（wave propagation），直到抵達終點，再沿著擴散路徑回溯，即可找到最短繞線路徑。

## 歷史背景

Maze Routing 由 C. Y. Lee 於 1961 年提出，發表在期刊 *The Bell System Technical Journal* 上，標題為 *"An Algorithm for Path Connections and Its Applications"*。這是最早被提出的自動化繞線演算法，靈感來自於「迷宮中最短路徑」的經典問題。

在 Lee 的時代，印刷電路板（PCB）和積體電路的繞線完全依賴人工。Lee 的演算法首次實現了計算機自動化繞線，為後續數十年的 EDA 繞線技術奠定了理論基礎。儘管此後出現了大量更高效的演算法，Lee 演算法的核心思想——波前擴散（wavefront expansion）——至今仍是所有網格繞線演算法的共同根基。

## 演算法步驟

Lee 演算法包含五個主要步驟：

### 1. 初始化

將起點（source）單元標記為成本 0，並將其加入波前（wavefront）佇列。

### 2. 波前擴散（Wave Propagation）

從波前中的每個單元出發，向其四個方向（上、下、左、右）的未訪問鄰居單元擴散。每擴散一步，將該鄰居單元標記為當前成本加 1，並將其加入新的波前。尚未被障礙物佔用且未訪問過的單元才可以被擴散。

這個過程持續進行，直到滿足以下兩種情況之一：要麼抵達了終點（target），要麼所有可擴散的單元都已被訪問而仍無法抵達終點（表示不存在可行路徑）。

### 3. 終止條件

擴散過程在以下兩種情況下停止：
- **成功**：波前擴散抵達終點，演算法繼續執行回溯步驟
- **失敗**：波前中的所有單元都已被擴散完畢，但終點從未被觸及，則表示不存在連接起點和終點的路徑

### 4. 回溯（Backtrace）

從終點開始，沿著成本值嚴格遞減的方向（即每一步都移動到成本比當前單元少 1 的相鄰單元），一路回到起點。這條路徑即為找到的最短路徑。

### 5. 清除（Clean Up）

將所有在擴散過程中標記的成本值清除（或使用單獨的遮罩層來儲存成本值，以便重複使用網格），為下一次繞線做準備。

## 波前擴散的本質

波前擴散類似於池塘中的漣漪：投下一顆石子（起點），漣漪以同心圓的形式向外擴散。從本質上講，Lee 演算法是在網格圖（grid graph）上執行的**廣度優先搜尋（BFS）**。

由於 BFS 的特性，所有邊的權重相同（每一步的成本為 1），因此第一次抵達終點時所找到的路徑一定是**步數最少**的路徑，即最短的路徑。

## 最優性保證

Lee 演算法保證找到起點和終點之間的**最短路徑**（以網格單元數量計算）。這是因為 BFS 探索節點的順序保證了：當某個節點第一次被訪問時，它一定是經由最短路徑到達的。

這一最優性保證是 Lee 演算法與啟發式搜尋（如貪婪演算法）之間最重要的區別。貪婪演算法可能因為只關注局部最優而錯過全局最短的路徑。

## 時間與空間複雜度

Lee 演算法的時間和空間複雜度均為 **O(N)**，其中 N 是探索過的網格單元總數。

在最壞情況下，如果網格尺寸為 m × n，且起點與終點位於對角，則 N ≈ m × n，此時複雜度為 **O(m × n)**，亦即 **O(n²)**（若 m ≈ n）。

這使得 Lee 演算法在處理大型網格時可能非常耗費記憶體和時間。對於一個 1000×1000 的網格，在最壞情況下需要探索一百萬個單元，這在計算資源有限的時代是難以接受的。

## 記憶體優化技術

為了解決 Lee 演算法記憶體消耗過大的問題，研究者提出了多種優化方案：

### 同心圓編碼（Concentric Circles Encoding）

不為每個單元儲存完整的成本值，而是只儲存到起點的距離所屬的同心圓層級。這種方法可以降低每個單元所需的儲存位元數。

### A\* 搜尋

將 Lee 演算法的 BFS 擴散改為 A\* 搜尋，加入啟發式函數（通常為曼哈頓距離）來引導搜尋方向，大幅減少需要探索的單元數量。詳見後文的比較章節。

### 替代編碼（Alternative Encoding）

使用**每單元 2 個位元**來儲存方向資訊（N/S/E/W），而不是儲存成本值。回溯時直接讀取方向位元即可找到路徑，無需依賴成本值。這種方法將每個單元的記憶體消耗從 8-32 位元降低到 2 位元，代價是無法直接得知距離。

### 雙向搜尋（Hasse 的改進）

同時從起點和終點進行波前擴散，兩個波前相遇時即找到路徑。這種方法可以將探索區域從一個半徑為 r 的圓縮減為兩個半徑為 r/2 的圓，探索面積約減少一半。

## 網格模型

在 Lee 演算法中，網格被建模為一個二維陣列，其中：

- 每個單元代表一條**繞線軌道交點**（routing track intersection）
- 空單元表示可用的繞線資源
- 障礙單元（已被佔用或禁止繞線的單元）無法被擴散通過
- 每個單元的成本值代表其到起點的距離

在實際應用中，網格可以包含多層（多層金屬繞線），此時每個單元還需記錄所在的層級，擴散時可包含垂直方向（切換層級）。

## 多端點網路（Steiner 樹）

Lee 演算法原本設計用於連接兩個端點，但可以擴展至連接多個端點（多端點網路）：

1. 找出所有端點對中距離最近的一對，使用 Lee 演算法連接它們
2. 將連接完成的路徑視為新的障礙/可繞線資源
3. 從已連接的網路部分出發，擴散至下一個最近的未連接端點
4. 重複此過程，直到所有端點都連接完畢

這種貪婪方法找到的 Steiner 樹可能不是全域最優的，但在實踐中效果良好。

## Lee 演算法與 A\* 的比較

Lee 演算法與 A\* 搜尋之間有著密切的關係：

| 特性 | Lee 演算法 | A\* 搜尋 |
|------|-----------|---------|
| 搜尋策略 | BFS（均勻成本） | 啟發式搜尋 |
| 成本函數 | 距離起點的步數 | f(n) = g(n) + h(n) |
| 啟發式 | 無 | 曼哈頓距離（典型） |
| 最優性 | 總是找到最短路徑 | 使用可容許啟發式時保證最優 |
| 收斂速度 | 慢（向所有方向均勻擴散） | 快（引導方向朝終點） |
| 記憶體 | 需要儲存所有探索過的單元 | 需要儲存 open set + closed set |
| 適用場景 | 需要絕對最短的路徑 | 需要「夠好」且快速的路徑 |

在 Lee 演算法的框架下，它就是一個在均勻成本網格上執行的 **Dijkstra 演算法**。而 A\* 可以視為 Lee 演算法的加速版本：在擴散時優先選擇那些距離終點更近（曼哈頓距離更小）的單元。

**在 eda4 專案中**，`v2f-pnr`（佈局佈線工具）實際使用的是 **A\* 演算法**而非 Lee 演算法，主要原因是 A\* 的搜尋效率更高——在 FPGA 繞線圖（tile + wire segment 圖）上，A\* 可以快速收斂到最優路徑，而 Lee 演算法的均勻擴散在大型 FPGA 器件上開銷過大。

## Rip-up and Reroute

在實際繞線中，多條繞線可能會互相衝突（共享相同的網格單元）。Rip-up and reroute 是一種迭代處理衝突的方法：

1. 依次繞線所有網路
2. 若有路徑重疊衝突，則**移除（rip up）**其中一條衝突的路徑
3. 將被移除的路徑重新繞線，避開其他已存在的路徑
4. 重複此過程直到所有衝突解決

這是 **PathFinder** 演算法的基礎。PathFinder 進一步引入了「擁擠度成本」的概念：在每次迭代中，增加對熱門資源的使用成本，引導繞線器避開擁擠區域，從而實現全域收斂。

## Hasse 的改進

基於 Hasse 等人的研究，Lee 演算法有多種重要的改進版本：

### 雙向搜尋

同時從起點和終點向中間擴散。兩個波前相遇時立即停止。對於大小為 n × n 的網格，探索區域約減半。

### 帶有前瞻的搜尋（Search with Lookahead）

在擴散時不只是看當前單元，還預先評估周圍區域的可繞性。如果前方區域被障礙完全封鎖，可以及早改變擴散方向。

### 基於框架的搜尋（Frame-based Search）

將搜尋限制在一個動態調整的「框架」（bounding box）內，框架以外被視為不可達區域。當在框架內找不到路徑時，逐步擴展框架。這種方法可以有效控制記憶體和時間消耗。

## 局限性

儘管 Lee 演算法在理論和實踐上都具有重要價值，但它有以下主要限制：

### 單一路徑

Lee 演算法每次只能處理一條路徑。它不具備全域視角，無法同時考慮多條繞線的整體佈局。所有多端點或多網路的問題都需要透過反覆呼叫單路徑繞線來解決。

### 記憶體消耗大

對於大規模網格，儲存所有單元的成本值可能需要巨大的記憶體空間。儘管有替代編碼等優化技術，但在超大規模設計中記憶體消耗仍然是瓶頸。

### 缺乏擁擠感知

基本的 Lee 演算法不考慮資源的擁擠程度。它只知道某個單元是否被佔用，但不知道該單元周圍的資源競爭情況。如果沒有 rip-up and reroute 或 PathFinder 的輔助，單純的 Lee 演算法在密集設計中容易產生繞線失敗。

### 速度

在大型設計中，均勻的波前擴散速度較慢。對於需要快速反覆運算的應用場景，A\* 或基於模式繞線（pattern routing）的演算法通常更受歡迎。

## 為什麼 Lee 演算法如此重要

儘管有上述局限，Lee 演算法被認為是 EDA 繞線領域的**奠基性演算法**，原因如下：

1. **開創了波前擴散範式**：波前擴散（wavefront expansion）的概念被後續所有基於網格的繞線演算法所繼承，包括 A\*、PathFinder、以及各種模式繞線演算法
2. **保證最短路徑**：在有路徑存在的前提下，Lee 演算法保證能找到最短的路徑，這在許多應用場景中是至關重要的
3. **簡單且可靠**：演算法邏輯簡單，易於實現和除錯，是初學者理解和實作繞線演算法的絕佳入門點
4. **可直接應用於多層繞線**：只需將擴展方向從 4 個增加到 6 個（上下左右 + 層級切換），即可處理多層繞線問題

## 在 FPGA 繞線中的應用

FPGA 的繞線架構由大量的繞線圖（routing graph）組成，其中：

- **節點（tile）**：代表 FPGA 中的可程式化互連點（如 PIP）
- **邊（wire segment）**：連接不同 tile 的金屬線段

Maze routing 可以直接應用於 FPGA 繞線圖：將 tile 視為網格單元，wire segment 視為可穿越的邊。Lee 演算法或 A\* 搜尋在 FPGA 繞線圖上尋找從源 tile 到目標 tile 的路徑，經過的路徑即為 FPGA 的程式化配置。

FPGA 的繞線圖通常不是簡單的二維網格——不同長度的 wire segment 提供了不同「跳躍距離」，這使得 Lee 演算法的成本計算需要考慮線段長度（而非均勻步數）。

## 在 eda4 中的關係

在 eda4 專案中，`v2f-pnr` 工具實作了基於 A\* 的繞線引擎，其核心邏輯是 Lee 演算法的直接後代。具體差異如下：

- Lee 演算法：BFS 擴散，無啟發式，保證最短路徑，但探索效率較低
- `v2f-pnr` 的 A\*：BFS + 曼哈頓距離啟發式，同樣保證最短路徑（因為啟發式是可容許的），但探索效率高得多

在 FPGA 繞線的實際應用中，探索效率比絕對最短路徑長度更重要，因為 FPGA 的繞線資源充足，路徑長几個 tile 的差異不大，但搜尋速度的差距卻可能高達數倍。因此 `v2f-pnr` 選擇了 A\* 作為核心繞線演算法。
