# ATPG（Automatic Test Pattern Generation）

## 什麼是 ATPG

ATPG（自動測試向量生成）是 EDA 中用於積體電路測試的關鍵技術。它的目標是自動產生一組輸入測試向量（test patterns），能夠檢測製造過程中可能出現的物理缺陷，確保晶片出廠時功能正確。

ATPG 有別於功能測試（functional test）：功能測試驗證晶片是否正確執行特定指令；而 ATPG 針對的是製造缺陷，目的在於以最少的測試向量達到最高的故障覆蓋率。

## 故障模型（Fault Model）

製造缺陷的種類繁多，ATPG 使用故障模型來抽象化這些物理缺陷。常見的故障模型包括：

- **Stuck-At 模型**：假設電路中的某條連線永久固定於邏輯 0（SA0）或邏輯 1（SA1）。這是最經典、最廣泛使用的模型。
- **Stuck-Open 模型**：CMOS 電晶體永遠關閉（斷路），導致浮動節點。
- **Transition Delay 模型**：信號從 0→1 或 1→0 的轉換比正常速度慢，導致時序違規。
- **Bridging 模型**：兩條無關的連線短路在一起，形成 wired-AND 或 wired-OR 行為。

### Stuck-At 模型的使用方式

以一個簡單的 NAND 閘為例，輸入為 a 和 b，輸出為 c：

- 若 c 存在 SA0 故障：正常情況下 `(a=1, b=1) → c=0`，但故障時 `c` 強制為 0。要活化這個故障，需設 `a=1, b=1`（正常輸出應為 0 才能使 D' 產生；實際上 SA0 需要正常輸出為 1 才顯出差異，所以正確是設 `a=1, b=1` 讓正常輸出為 0，故障輸出也是 0——這沒有差異。正確來說：SA0 要活化需設正常值為 1，所以對 NAND 閘，設 `a=0`（不管 b）即讓輸出正常為 1，但故障節點強制為 0，產生 D'）
- 若 c 存在 SA1 故障：要活化需設正常值為 0，即 `a=1, b=1`，此時正常輸出 0 而故障輸出 1，產生 D

### 等效故障（Equivalent Faults）

不同節點的不同故障可能對電路行為產生完全相同的影響。這些故障稱為等效故障，可以合併處理：

- NAND 閘：輸入 SA0 等效於輸出 SA1
- NOR 閘：輸入 SA1 等效於輸出 SA0
- 反相器：輸入 SA0 等效於輸出 SA1，輸入 SA1 等效於輸出 SA0

利用等效故障可以將故障列表縮減為等效類別的代表，減少需要處理的故障數量。

### 故障支配（Fault Dominance）

若檢測到故障 f1 的所有測試向量也能檢測到故障 f2，則 f2 被 f1 支配。被支配的故障可以從列表中移除，因為只要產生測試向量檢測 f1 就自動檢測了 f2。

### 故障壓縮（Fault Collapsing）

結合等效與支配的概念，可以將原始故障列表壓縮至 50-60% 的大小：

1. 識別所有等效類別，每類保留一個代表
2. 在等效壓縮後的列表中，識別支配關係，移除被支配的故障
3. 最終的壓縮列表用於 ATPG 處理

## 單一 Stuck-At 故障模型

單一 stuck-at 模型（SSF，Single Stuck-At Fault）是 ATPG 中最基本的假設：

- 每次只考慮一個節點存在故障
- 該節點要麼 stuck-at 0（永遠為 0），要麼 stuck-at 1（永遠為 1）
- 電路中其他所有節點都正常工作

雖然這個假設在現實中可能不成立（多個缺陷並存），但實踐證明 SSF 模型能有效檢測大部分製造缺陷，且測試向量數量可控。

對於 n 個節點的電路，可能的 SSF 故障數量為 2n 個（每個節點：SA0 與 SA1）。

## ATPG 的基本流程

ATPG 的核心過程包含兩個步驟：

1. **故障活化（Fault Excitation）**：在故障節點上設置與故障值相反的信號值。例如若節點存在 SA0 故障，則需要設該節點為 1 以活化故障；若為 SA1，則需設為 0。活化的目的是讓故障效應顯現。

2. **故障傳播（Fault Propagation）**：將故障節點上的異常值（D 或 D'）沿著一條或數條路徑傳播到至少一個主要輸出（Primary Output），使外部觀察者能檢測到故障。

## D 演算法（D-Algorithm）

D 演算法由 J. Paul Roth 於 1966 年提出，是歷史上第一個完整的 ATPG 演算法。

### D 運算（D-Calculus）

D 演算法使用五值邏輯系統：0、1、D、D'、X（未知）。

- **D**：在正常電路中為 1，在故障電路中為 0
- **D'**（也寫作 D-bar）：在正常電路中為 0，在故障電路中為 1

例如，一個 SA0 故障節點的輸出是 D（正常為 1，故障為 0）；一個 SA1 故障節點的輸出是 D'（正常為 0，故障為 1）。

### D 前沿（D-Frontier）

D 前沿是由所有**至少一個輸入有 D 或 D'、但輸出尚未確定**的邏輯閘構成的集合。ATPG 演算法透過 D 前沿來追蹤故障效應的傳播進度。

### J 前沿（J-Frontier）

J 前沿是由所有**輸出值已確定但輸入尚未完全確定**的邏輯閘構成的集合。這些閘需要透過「正推」（implication）或「反推」（justification）來滿足其輸出值的需求。

### 演算法步驟

1. **故障活化**：在故障節點上設定 D 或 D'（取決於故障類型）
2. **D 驅動（D-Drive）**：選擇 D 前沿中的一個閘，設定其未確定的輸入以使 D 或 D' 通過該閘向輸出傳播
3. **蘊含（Implication）**：傳播新賦值的影響，計算所有可推導的信號值
4. **正推（Justification）**：處理 J 前沿，反推信號值直到所有內部信號都追溯到主要輸入
5. **衝突回溯**：若某個閘的輸出無法被正輸入滿足，則發生衝突，需要回溯嘗試其他選擇

D 演算法是**完備**的（complete）——如果存在測試向量，它一定能找到。但其效率較差，因為它在整個電路的閘等級進行搜尋，回溯次數可能非常多。

## PODEM（Path-Oriented Decision Making）

PODEM 由 Prabhakar Goel 於 1981 年提出，是對 D 演算法的重大改進。

### 核心思想

PODEM 的關鍵洞察是：**只對主要輸入（Primary Input）進行賦值**，所有內部信號值通過邏輯蘊含自動推導。這意味著不需要 J 前沿——只要 PI 賦值確定，整個電路的行為就完全確定。

### 目標導向（Objective-Oriented）

PODEM 引入**目標**（objective）的概念。目標是「當前的需求」，例如「把某個閘的輸出設為 1」或「把某個閘的輸入設為 0」。

演算法為每個目標回溯找到一個可滿足該目標的 PI 賦值。

### 演算法步驟

1. **設定初始目標**：將故障節點設為活化值（如為 SA0 設為 1）
2. **回溯（Backtrace）**：從當前目標往主要輸入回溯，找到一個 PI 賦值
3. **蘊含**：賦值 PI 後，模擬推導所有內部信號值
4. **檢查 D 前沿**：
   - 若 D 前沿非空且可傳播到 PO，繼續下一步目標
   - 若 D 前沿為空（故障效應被阻斷），則回溯嘗試其他 PI 賦值
5. **若故障效應到達 PO**：找到測試向量，成功
6. **若所有 PI 組合都試過**：該故障不可測

### PODEM 的優勢

PODEM 比 D 演算法更高效的原因：

- 決策空間從所有閘的輸入縮小到只有主要輸入
- 目標導向搜尋避免了無謂的探索
- 自動蘊含消除了 J 前沿的複雜管理

## FAN（Fanout-Oriented ATPG）

FAN 由 Hideo Fujiwara 與 Takeshi Shimono 於 1983 年提出，在 PODEM 的基礎上進一步改進。

### 多路回溯（Multiple Backtrace）

PODEM 一次只處理一個目標，回溯產生一個 PI 賦值。FAN 則可以同時追蹤多個目標，在回溯過程中收集所有目標的資訊，最後分配一組一致的 PI 賦值。

多路回溯的流程：

1. 從初始目標開始，沿著電路向主要輸入方向回溯
2. 在每個階段同時處理多條回溯路徑
3. 在分歧點（fanout point）分割目標，繼續各自的回溯
4. 最終將所有需求匯總到主要輸入上，一次賦值滿足所有目標

這減少了回溯次數與決策的總數。

### 頭線（Head Lines）

頭線是電路中**扇入錐（fanin cone）中不含任何分歧點**的連線。頭線的重要性在於：

- 對頭線的賦值不會與其他電路區域的決策發生衝突
- 頭線的賦值可以提前確定並獨立處理
- 頭線的識別大幅簡化了回溯引擎的複雜度

### 唯一敏化（Unique Sensitization）

FAN 能夠識別出某些局部路徑是故障傳播的「唯一路徑」——如果這些路徑被阻斷，故障就無法被傳播到任何輸出。FAN 會自動分配這些唯一路徑所需的賦值，而不需要等待目標回溯。

### FAN 的優勢

FAN 在 PODEM 的基礎上減少了更多的回溯次數：

- PODEM 對於某些困難電路可能產生大量回溯
- FAN 透過多路回溯與頭線處理，在同樣的電路上表現更穩定
- FAN 是 ATPG 後續研究的基準

### D 演算法的五值邏輯真值表

以 AND 閘為例的五值邏輯真值表：

| A | B | AND |
|---|---|-----|
| 0 | X | 0   |
| 1 | X | X   |
| D | 1 | D   |
| D | 0 | 0   |
| D | D | D   |
| D | D'| 0   |
| D'| 1 | D'  |
| D'| 0 | 0   |
| X | X | X   |

其他閘（OR、NAND、NOR、XOR）的規則類似，遵循對偶關係。

### D 演算法的回溯機制

D 演算法的回溯涉及兩個層面：

- **D 驅動的回溯**：當一個 D 前沿選擇失敗（無法成功傳播到 PO）時，嘗試 D 前沿中的其他閘，或改變傳播路徑上的賦值
- **J 前沿的回溯**：當某個閘的輸出值無法被輸入正推滿足時，改試其他輸入組合

這種雙層回溯使 D 演算法保證完備，但也導致效率問題——在最壞情況下，演算法可能探索所有閘的所有輸入組合。

### PODEM 的目標回溯細節

PODEM 的目標回溯過程更具體地如下：

1. 給定一個目標 `(line, value)`，例如 `(g, 1)` 表示要把線 g 設為 1
2. 從 g 開始，沿著電路向主要輸入回溯
3. 在每個閘：
   - 若為 AND 閘且目標值為 1：所有輸入必須為 1——選擇一個 X 狀態的輸入作為新目標
   - 若為 AND 閘且目標值為 0：至少一個輸入為 0——選擇最容易控制的輸入
   - 若為反相器目標值 v：輸入的目標為 NOT v
4. 到達 PI 時，將 PI 設為回溯得到的值
5. 執行蘊含，檢查 D 前沿的變化

## 三種演算法的比較

| 特性 | D-Algorithm (1966) | PODEM (1981) | FAN (1983) |
|------|-------------------|-------------|------------|
| 決策對象 | 所有閘的輸入 | 只對主要輸入 | 主要輸入 + 頭線 |
| 需要 J 前沿 | 是 | 否 | 否 |
| 回溯方式 | 閘等級 | PI 回溯 | 多路回溯 |
| 目標導向 | 部分 | 是 | 是 |
| 頭線處理 | 無 | 無 | 有 |
| 效率 | 較低 | 較高 | 最高 |

## ATPG 在 eda4 中的相關性

ATPG 與 JTAG 邊界掃描（另見 jtag_spi.md）密切相關：

- JTAG 的 EXTEST 指令使用邊界掃描暫存器（BSR）測試晶片間的互連
- 邊界掃描測試需要 ATPG 自動產生測試向量，以檢測 PCB 上的焊接缺陷與開路/短路
- 透過 JTAG 鏈，ATPG 生成的測試向量可以序列化輸入，並序列化輸出比對

**邊界掃描的 ATPG 特點**：

- 不需要探針接觸，透過 JTAG 的四條信號線即可完成測試
- 可以測試晶片間互連（interconnect）而無需物理接觸
- 最常見的故障類型是板上焊接的 SA0/SA1 與 bridging 故障

## FPGA 的測試考量

對於 FPGA 晶片（如 iCE40）：

- **製造商測試**：Lattice 等 FPGA 製造商在出廠前已進行全面測試，包括內部邏輯單元、BRAM、DSP、PLL 等
- **使用者測試**：使用者層級的測試主要集中在 PCB 層面的互連與 I/O

iCE40 晶片沒有提供使用者可存取的內部掃描鏈（scan chain）。這意味著傳統的掃描設計 ATPG 無法直接應用於 iCE40 的內部邏輯。

但使用者仍可透過以下方式進行測試：

- JTAG 邊界掃描的 EXTEST 指令測試板上互連
- SAMPLE/PRELOAD 指令觀察 I/O 腳位狀態
- 設計內建自我測試（BIST，Built-In Self-Test）電路，在使用者邏輯中實現測試模式

## 故障覆蓋率（Fault Coverage）

故障覆蓋率的定義：
```
故障覆蓋率 = (檢測到的故障數) / (總故障數)
```

- 典型的 ASIC 製造測試目標是 >95% 的 stuck-at 故障覆蓋率
- 對於安全關鍵應用（如汽車、航空），目標通常 >99%
- 故障覆蓋率可透過故障模擬（fault simulation）進行評估

### 可測性與不可測故障

並非所有故障都能被檢測。故障不可測的原因包括：

- **冗餘邏輯**：電路中的冗餘閘使得某些故障不影響任何輸出
- **OSC（Observability Don't Care）**：某些節點的值無法被傳播到任何主要輸出
- **CDC（Controllability Don't Care）**：某些節點無法被設定成需要的值

可測性分析（Controllability/Observability 分析）常用於評估電路的測試難度，並指導 DFT 設計。

### SCOAP 可測性度量

SCOAP（Sandia Controllability/Observability Analysis Program）是經典的可測性分析演算法：

- **CC0(v)**：將線 v 設為 0 所需的賦值數量
- **CC1(v)**：將線 v 設為 1 所需的賦值數量
- **CO(v)**：觀察線 v 值的難度（需設定的其他線數量）

SCOAP 值越高表示越難控制或觀察。在 DFT 設計中，可以針對 SCOAP 值高的節點加入測試點（test point）來提高可測性。

## 現代 ATPG 技術

當代 ATPG 在經典演算法的基礎上增加了許多實用技術：

- **測試壓縮（Test Compression）**：使用 XOR 樹（MISR，Multiple-Input Signature Register）將多個輸出壓縮為簽名，減少測試資料量
- **At-Speed 測試**：使用過渡故障（transition fault）模型，以真實時脈頻率測試晶片能否在時序約束下正確運作
- **低功耗測試（Low-Capture-Power ATPG）**：在測試模式下，電路的翻轉率（toggle rate）遠高於正常工作，可能導致過熱或壓降；低功耗 ATPG 透過 X-filling 與測試向量修改來降低功耗
- **診斷 ATPG（Diagnostic ATPG）**：除了檢測故障的存在，還能定位故障的精確位置，用於良率分析（yield analysis）

這些技術共同確保了現代 VLSI 晶片在量產時能以合理的成本達到所需的品質水準。
